# Exact versions for the provider SDKs and the HTTP stack beneath them.
#
# Applied to every install through the `-c constraints.txt` line in requirements.txt, so
# the server image, CI, pip-audit and the desktop sidecar build all resolve this set —
# no build path has to remember a flag.
#
# Why these and not a lock of everything: these are the packages whose upgrades change
# how a provider call *behaves* — what is retried, what is raised, how connections are
# pooled and verified — and they arrived as transitive floats. openai 2.x → 3.x came in
# with no diff in this repository, only langchain-openai widening its own range, and
# narrowed which transport errors the SDK retries: a latent cross-event-loop bug in the
# worker that 2.x had been retrying away (sending the request twice) became a failed run
# (backend/AGENTS.md, "One event loop per worker process"). All are pure Python, so one
# pin resolves identically on Linux, macOS and Windows.
#
# Upgrading is a reviewed change: backend/AGENTS.md, "Provider SDKs are pinned".
