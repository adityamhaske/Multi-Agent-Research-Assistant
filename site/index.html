Multi-Agent Research Assistant

A research assistant that searches, cites every claim, and stops for your approval before it finalises anything. Bring your own key — or run it entirely offline.

What it does

A pipeline of agents — planner, executor, critic, synthesizer — researches a question, gathers evidence, and drafts a cited report. It then pauses at a durable checkpoint and waits for you to approve, revise, or reject it. Only then does it finalise.

Citations that resolve

Every [n] maps to a real source and the verbatim snippet supporting it. When a citation cannot be verified, it says so rather than rendering clean.

A human approval gate

The run halts before finalising. You see the evidence and decide — nothing is finished on your behalf.

Your model, your provider

Anthropic, Google, OpenAI, OpenRouter, a local Ollama model, or any custom OpenAI-compatible endpoint — with a different model per role if you want.

Works offline

Corpus mode answers from documents you upload, with no network calls at all. Your files never leave the machine.

Auditable exports

Export Markdown, PDF, or a .bundle.json carrying every claim, snippet, content hash, model and cost — verifiable offline by a standalone checker.

No account required

The desktop app has no login and keeps everything in local SQLite. Provider keys live in your OS keychain.

These builds are not code-signed. This is a free, open-source project without an Apple Developer subscription, so macOS refuses to open the app on first launch and reports that it cannot verify the developer. That warning means the app is unsigned — not that something is wrong with it. Clearing it takes about six clicks, once.

First launch on macOS

  1. Open the .dmg and drag the app into Applications.
  2. Double-click it. macOS refuses to open it and mentions an unverified developer.
  3. Open System Settings → Privacy & Security.
  4. Scroll to Security. A line about the blocked app appears — click Open Anyway.
  5. Authenticate, then confirm once more. Later launches open normally.

Windows and Linux bundles are built by CI but have not been launch-tested; macOS on Apple silicon is the verified platform today.

How to use it

  1. Open the app. It starts on a finished demo report, so you can see how citations, evidence and the approval gate work before configuring anything.
  2. Connect a model. Open Settings and add a provider key, or point it at a local Ollama server. Keys are validated against the provider before being stored, and they go into your OS keychain — never a plain-text file.
  3. Ask a question. Choose a depth: fast, balanced, or comprehensive.
  4. Watch the pipeline. Planner, executor, critic and synthesizer run in turn, streaming progress as they go.
  5. Approve or send it back. The run stops at the gate with a draft and its evidence. Approve it, or return it with feedback for another pass.
  6. Export. Markdown, PDF, or an auditable .bundle.json. You can also ask follow-up questions grounded in the approved report.

Deploy it yourself

Beyond the desktop app, the full stack — API, worker, frontend, Postgres and Redis — runs under Docker. Use this when you want several users, or a shared instance on a server.

Run the whole stack

git clone https://github.com/adityamhaske/Multi-Agent-Research-Assistant.git
cd Multi-Agent-Research-Assistant
./start.sh

Requires Docker with Compose v2. The script writes a .env if one is missing, generates a JWT secret, builds the images, waits until every service reports healthy, and opens the app at http://localhost:3031.

./start.sh --fake     # keyless demo, no API key needed
./start.sh --logs     # start, then follow logs
./start.sh --stop     # stop, data preserved
./start.sh --reset    # stop and delete all data

Notes for a real deployment

  • Postgres must be a pgvector image — the migrations enable the extension and create a vector column.
  • Set ENVIRONMENT=production for secure cookies and a disabled docs endpoint.
  • Set ENCRYPTION_KEY explicitly, so rotating the JWT secret does not invalidate stored user keys.
  • Leave the shared provider keys unset to require every user to bring their own.
  • Put a TLS reverse proxy in front; a sample Caddyfile ships in deploy/.

Container images are published to GHCR for linux/amd64 and linux/arm64, so they run on ARM servers as well as x86.
