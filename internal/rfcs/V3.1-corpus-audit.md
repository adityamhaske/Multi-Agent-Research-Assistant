- Ingest DOCX, Excel (XLSX/XLS), CSV, PDF and other common research formats.

## 1. What exists today

### 1.1 Ingestion and formats
- **One extraction function.** `backend/research_engine/documents.py::extract_document(filename, data) -> (text, page_starts, kind)` (:58-80) is dispatched by `kind_for` (:34-55). It runs off the event loop through `asyncio.to_thread` from `CorpusStore._prepare_sync` (`corpus.py:347`, `:389`).
- **Accepted formats:**
  - `.pdf` → `pdf`.
    - pypdf is imported lazily (:84).
    - Encrypted PDFs are refused (:91-94). The limit is 2000 pages.
    - A PDF with no extractable text is refused as needing OCR (:114-115).
    - A page whose extraction throws becomes `""` without any warning (:105-108), so a partly scanned PDF is accepted with its image-only pages missing.
  - `.html` / `.htm` → `html`. Parsed with bs4 and lxml; script, style, noscript and template are dropped (:119-146).
  - `.md` / `.markdown` → `md`.
  - `.txt`, `.text`, `.rst`, `.csv`, `.json` → `txt`. Decoded as UTF-8 with `errors='replace'`, CRLF becomes LF, and `page_starts=[0]` (:77-80). CSV therefore has no row or column structure.
  - Everything else raises `ValueError` under the citation-grade rule (:47-54).
- **Size limits.**
  - 25 MiB per file: `documents.py:20`, checked again in `corpus_ingest.clean_upload` (:57-60).
  - Both hosts read the whole body into memory first (`app/api/v1/corpus.py:77`; `desktop/sidecar.py:2541`).
  - There is **no decompressed-size limit**.
- **Shared upload contract** (`backend/app/services/corpus_ingest.py`):
  - The name is reduced to its basename (:52).
  - `ValueError` maps to `Invalid` (:80-99). `ImportError` is not caught, so a missing parser becomes a 500.
- **Chunking** (`chunking.py::chunk_document`, :257-325):
  - Each chunk is a verbatim `[start,end)` span with `text == source[start:end]`.
  - Size is about 1200 characters, with 180 overlap and a 200 minimum. Splits fall on paragraph or sentence breaks (:242-247).
  - `page` is the page where the chunk **starts**. It is `None` when there are one or fewer page starts (:304), so a single-page PDF carries no page.
- **Embedding.** The exact chunk text is embedded in batches of 32 and stored as a float32 blob with `embedding_model` on each chunk (`corpus.py:352-355`, `:510-521`).
- **Duplicates and versions.**
  - Duplicates are caught by `UNIQUE(filename, sha256)` (`corpus.py:169-170`).
  - When a `doc_key` is passed, only the current version's sha is compared (:400-407).
  - A new version is created only when the caller passes an explicit `doc_key` (:321-346, :446-508).
- **Approved reports** are ingested automatically as `report-<id>.md` with `origin='generated'`, by `app/services/report_corpus.py:49-66`. The call sites are `runs.py:675-694`, `pipeline_runner.py:328-349` and `sidecar.py:2749-2772`.
- **Parsing dependencies** are pypdf, bs4, lxml and numpy only (`requirements.txt:50-58`). There is no docx, xlsx, pptx, odf or OCR library. `research_engine/pyproject.toml` (:29-43) omits pypdf and numpy.

### 1.2 Storage and scoping
- **Server.** One SQLite file per project, `corpus_<project_id>.sqlite`, under `settings.corpus_path` (`app/adapters.py:148-202`; `config.py:85`, `:180-196`).
  - `for_project` returns `None` when the file is absent.
  - Deleting a project unlinks the `.sqlite`, `-wal` and `-shm` files.
- **Desktop.** One `corpus.sqlite` for the whole app, embedded with `LocalEmbeddings` (`sidecar.py:657-669`).
  - `_DesktopCorpusLocator` ignores `project_id`, and its `delete` and `paths_to_delete` do nothing (`sidecar.py:848-871`).
  - **Every desktop project lists, searches and chats over every other project's documents.** Deleting a project leaves its documents behind.
  - `tests/workflow/test_desktop_contract_gaps.py:199-219` pins this: the per-project response equals the flat one.
- **Schema migration** happens in code through `CorpusStore._migrate` (additive and idempotent; `corpus.py:253-306`), not Alembic.
  - `_SCHEMA_VERSION=2` is written only when the meta row is first inserted (:204, :276-281).
  - There is no downgrade path.
- **No folder, path, MIME type, tag, collection or selection** exists anywhere in the store.
- **Run snapshot.** Corpus-mode runs write `research_runs.corpus_id` and `corpus_version` (`run_execution.py:598-612`; Alembic 0024). Nothing reads them back:
  - they are not in `GET /runs/{id}` (`runs.py:212-236`);
  - they are not in the bundle (a grep of `run_bundle.py`, `bundle.py` and `verify_bundle.py` finds no "corpus").

### 1.3 Retrieval and grounding
- **One switch:** `RunConfig.corpus_mode: bool = False` (`runconfig.py:76-80`).
  - In corpus mode, `retrievers.search` sends every query to `get_corpus().search`, ahead of both the fake fixtures and the cache (`retrievers.py:92-96` vs `98-118`).
  - `tools.read_webpage` resolves **any** `corpus://` URL through the port, even when `corpus_mode` is off (`tools.py:111-117`). It refuses non-corpus URLs only when `corpus_mode` is on (:119-128).
- **Port.** The port is a ContextVar.
  - Its default, `NoCorpus`, raises on search, so a corpus run with nothing installed fails closed (`corpus.py:66-99`).
  - The protocol is `search(query, max_results)` and `read(url)`, with **no scope argument** (`ports.py:83-99`).
- **Where the port is installed:**
  - the server installs it only for corpus-mode runs (`run_execution.py:524-532`, `615-634`);
  - the desktop installs its app-wide store for **every** run (`sidecar.py:1615-1621`).
- **Search** (`_search_sync`, `corpus.py:554-573`):
  - It loads every chunk for the current model, filtered by `origin != 'generated' AND superseded_at IS NULL`.
  - It scores with brute-force numpy cosine, keeps the top `max_results*4`, drops scores of 0 or below, and returns **at most one hit per document** (:628-665, :651-655).
  - The empty-result diagnostics re-run the filters (:575-626; the comment at :582-587 says they must).
- **Read** (`read()`, `corpus.py:715-758`):
  - It resolves any document id in the file, including superseded and generated ones.
  - It refuses spans past the end of the text and returns the span with ±600 characters of context (capped at 8000).
  - Its title is `filename (page N, chars S-E)`.
  - Its only production caller is `tools.read_webpage`.
- **Locator:** `corpus://<doc-id>#chars=S-E[&page=N]` (`corpus.py:112-116`).
  - The backend parser is a **strict regex fullmatch** (:129-141, :134), so any new fragment key makes it return `None`.
  - The frontend parser (`lib/corpusLocator.ts:39-58`) uses URLSearchParams and tolerates extra keys.
- **Grounding:**
  - A quote must occur in what the tools returned for that URL (`graph.py:383-397`, `:470-474`). This check runs in **real mode only** (`graph.py:928-941`).
  - A verified quote can sit anywhere in the chunk or its ±600-character window. The URL therefore locates the retrieved chunk, not the quote itself.
  - The fidelity pass keeps the text of an unsupported claim and adds "(citation could not be verified)". Limitations sentences are exempt (`graph.py:1186-1411`).
  - A run with no evidence goes to the failer (`graph.py:1822-1839`).
  - **Nothing stops uncited prose from drawing on what the model already knows.**
- **Prompts:**
  - They are written for web research; there is no corpus-specific prompt.
  - The critic requires "at least 2 independent sources" (`prompts.py:44-47`) **[spot-checked]**.
  - `executor.main`, `critic.research` and `synthesizer.main` can be overridden by the user (`prompt_composition.py:79-87`).
- **Airgap checks:**
  - `CorpusStore._require_local_embedder_in_corpus_mode` (`corpus.py:525-552`) treats a missing `is_local` as remote, and decides locality by the endpoint host.
  - The hosts separately check the embedder model-id prefix (`ollama:` / `local:`) in `run_execution.py:623-626` and `pipeline_runner.py:207-221`.
  - **Nothing checks where the chat-model calls go.**
- **Source rows:**
  - Sources are keyed by the full URL including the fragment, so one document cited at two spans becomes two sources (`graph.py:351-360`, `1478-1510`).
  - `Source.corpus_document_id` stores everything after `corpus://`, `#chars=…` included (`run_lifecycle.py:345-347`) **[spot-checked]**.
- **Fakes:**
  - The scripted executor in corpus mode calls the real `retrievers.search` (`fakes.py:279-330`).
  - The real-mode fake provider has no corpus branch (`tests/fake_provider.py:41`, `117`).

### 1.4 API on both hosts
- **Server corpus routes** live under `/api/v1/projects/{project_id}/corpus` (`app/api/v1/corpus.py:39-162`). Every route authorizes through `resolve_project` and returns 404 for another user's project.
  - `POST /documents`: multipart `file` plus an optional `doc_key` form field; returns 201 `DocumentResponse`.
  - `GET /documents`: a bare list.
  - `GET /documents/{id}/download`: PDF is served inline; everything else as an attachment with a sandbox CSP.
  - `DELETE /documents/{id}`: 204.
  - `GET /status`.
- **Desktop corpus routes:**
  - the same five per-project paths, delegating to the server functions through `@delegates_to` (`sidecar.py:2584-2660`);
  - plus four flat `/corpus/*` routes of its own, including a raw-body upload with `?filename=` (`sidecar.py:2532-2555`). These are listed in `INTENTIONAL_DESKTOP_ONLY` (`test_host_parity.py:140-143`).
- **Runs:**
  - `CreateRunRequest.corpus_mode: bool` is the only corpus field (`app/schemas/runs.py:26-48`). It goes through `run_lifecycle.create_run` (:77-111) to the row.
  - The row → `RunConfig` hop exists in all four builders: `run_execution.py:178`, `pipeline_runner.py:114`, `sidecar.py:1394` (`_drive_session`) and `sidecar.py:1576` (`_drive_run`).
- **Chat:**
  - `ChatScope` is `report | corpus | web | everything` (`chat_scope.py:38`).
  - The corpus scope searches the whole store with `k=5` under a temporary `corpus_mode=True` (`chat_scope.py:113-142`).
  - Report chat exists only for sessions (`/research/{id}/chat`; the desktop copy is at `sidecar.py:1885-1996`).
  - **Runs have no chat on either host.** Project chat (`/threads`) is server-only because it needs pgvector.
- **Shared application layer.** `app/handlers/` is empty (`__init__.py:1-15`).
- **Size ceiling.** `sidecar.py` has 3063 lines against a ceiling of 3065 **[spot-checked]**.

## 4. Invariants and traps any implementation must respect

### 4.1 Two hosts, one contract
Every corpus behaviour has several homes. Change all of them together.

| Behaviour | Homes |
|---|---|
| Corpus location | `ServerCorpusLocator` (`adapters.py:148-202`) and `_DesktopCorpusLocator` (`sidecar.py:848-871`) |
| Upload signature | server `api/v1/corpus.py:54-77`; sidecar delegated route, which **restates the signature** (`sidecar.py:2606-2626`); sidecar flat raw-body route (2532-2541) |
| Response shaping | one function each: `corpus_ingest.document_response` and `status_response`. A parity test must compare against the **server's** contract (`test_desktop_contract_gaps.py:233-246`) |
| Port installation | `run_execution._corpus_port` (615-634), only when `corpus_mode` is on; `sidecar._drive_run` (1615-1631), always |
| Local-embedder check | three homes: `corpus.py:537-552` (by endpoint); `run_execution.py:623-626` and `pipeline_runner.py:207-221` (by model-id prefix) |
| Format list | five homes: `kind_for` plus its message, `document_headers._MEDIA_TYPES`, frontend `ACCEPTED`, `kindForFilename`, docs |
| 25 MB limit | `documents.py:20`, `corpus_ingest.clean_upload`, `corpus/page.tsx:34` |
| Download URL | `DocumentPreview.tsx:222-224` and `queries.ts:762-764` |
| Generated-report ingest | `runs.py:675-694`, `pipeline_runner.py:328-349`, `sidecar.py:2749-2772` |

- Every `/projects/*` operation served by both hosts must resolve to **the same function object** (`test_one_canonical_owner.py:311-326`). There is no divergent table for `/projects`.
- Folder and selection identity belongs in the **data**, never in the file path. Keep the per-project route as the one contract, with no `isDesktop` branch. If a capability really differs by host, expose it through `lib/capabilities.ts`.

### 4.2 The request → row → `RunConfig` hop
- AGENTS.md: "A field on the row is not a field the run reads." `corpus_mode` once lost this hop on both hosts. Installing the port is not the same as scoping it (comment at `run_execution.py:173-178`).
- A selection must be read in `run_config_for_run` (`run_execution.py:166-179`) **and** `sidecar._drive_run` (1566-1577). Whether the session builders carry it is disputed; see C1.
- A selection is control-plane data:
  - add it to `CONTROL_PLANE_FIELDS` (`tests/security/test_prompt_override_reach.py:42-51`);
  - never add it to `PREFERENCE_FIELDS` (`app/services/run_config.py:51-57`).
- Decide whether it is frozen at run start or re-read on resume. `prompt_overrides` is the frozen-at-start precedent.
- The search cache key is only query plus k (`retrievers.py:112`). Scoped search must never go through it.
- A test that builds `RunConfig` by hand cannot catch a missing hop (comment at `test_corpus_egress.py:205-217`).

### 4.3 Airgap and egress proof
- `is_local` defaults to remote (`docs/13:80-83`).
- The template is `test_corpus_egress.py`: it patches socket and DNS calls and drives the real host builders from a real row (:40-67, :261-357).
- **Do not stub `CorpusStore` search or read, and do not hand-build `RunConfig`.** The egress test once stayed green while the query embedding leaked.
- A leakage proof must assert that every retrieved or cited `Source.corpus_document_id` (after parsing off the fragment) is in the selection.
- Fake mode skips `verify_evidence_snippets` (`graph.py:928-941`). Real-mode quote fidelity needs a corpus branch in `tests/fake_provider.py`.
- A parser must not reach the network while parsing. That rules out docling (it fetches models from the Hugging Face hub) and makes markitdown/magika suspect (R6).

### 4.4 The citation locator contract
- **Verbatim spans.** Chunk text equals `source[start:end]` (`chunking.py:216-236`), and the embedded text is that same text (`corpus.py:352`).
  - Repeating a header row in each chunk breaks this unless the header is written into the extracted text itself.
  - The alternative is to separate the embedded text from the stored span, which is a schema change plus a retrieval eval.
- **`chars` is the authoritative locator; `page` is the page where the chunk starts.**
  - The backend regex is strict (`corpus.py:134`): extend the parser before any code emits a new key.
  - The frontend parser tolerates extra keys.
- **The accepted set and the refusal message are one contract**, pinned by `test_html_documents.py:46-53` and `test_corpus_store.py:185-189`.
- **The extracted text is what citations are checked against.**
  - Converters that rewrite content (to Markdown, for example) break verbatim matching.
  - Parsers that float on `>=` floors can let the server and desktop disagree on offsets for the same file. `constraints.txt` is scoped to provider SDKs today.
- **`read()` must keep resolving superseded versions** (`test_corpus_versioning.py:198-208`) while refusing documents outside the selection.

### 4.5 The P0 honesty rule
- **Derived text must be marked.** OCR output and linearized tables are not the user's original bytes and must be distinguishable. A new attestation grade means widening a CHECK constraint:
  - **On the server:** an Alembic migration.
  - **On the desktop:** the additive sync does **not** apply CHECK changes to existing files. `test_desktop_column_sync.py:232-250` pins this **[spot-checked]**. It needs a hand-written table rebuild like `_rebuild_legacy_agent_logs` (`sidecar.py:361-428`).
- **Diagnostics must repeat the selection filter** (`corpus.py:582-587`), or an empty selection is misreported as "wrong embedding model" or "corpus empty".
- **Failures stay distinct.** "Empty selection", "no match" and "unreadable" are three failures, and each must surface visibly. None may fall back to the model's own knowledge.
- **Generated reports are never evidence** (`corpus.py:562-571`; `test_report_corpus.py:36-82`). A selection must not readmit them, and the UI should exclude them or label them.
- **Unmeasured is not zero.** Counts must not render 0 for a query that failed or has not loaded; `corpus/page.tsx:422/430` already breaks this. Eval scope metrics that were not measured must say "unmeasured".
- **Network claims.** See C7. "Only from selected files" is a retrieval claim. It says nothing about where model calls go unless routing is enforced.
- **Scope copy is a claim** (`chat_scope.py:48-58`; `ScopeSelector.tsx:5-18`). Record what the run actually read: the resolved selection plus `corpus_id`/`corpus_version`.

### 4.6 Host parity tables
- `DESKTOP_UI_CALLS` (`test_host_parity.py:222-288`) must list every new path the UI calls.
- `KNOWN_DESKTOP_GAPS = {}` is capped at 0 (:303, :327-338).
- `INTENTIONAL_SERVER_ONLY` / `INTENTIONAL_DESKTOP_ONLY` (:107-111, :140-143).
- Shared routes must declare the same `response_model` on both hosts, or the shape check silently skips them (:381-414).
- The golden corpus journey (`tests/parity/journeys.py:189-266`, `golden/corpus.json`) is re-recorded from the server with `PARITY_RECORD=1`.
- `sidecar.py` is at 3063 of 3065 lines (`test_sidecar_is_transport_only.py:74`). Raise the ceiling only deliberately, and prefer thin delegating wrappers.

### 4.7 Layer boundaries
- `research_engine` never imports `app` or `evals` (`backend/AGENTS.md:7-14`). Extractors and locator logic belong in the engine; where the storage lives belongs to the host locators.
- `app/handlers/`:
  - It may not import FastAPI, `app.config`, `app.db`, `app.dependencies`, `app.adapters`, `app.workers`, celery, redis, keyring or `desktop`. Deferred imports count (`test_layer_boundaries.py:49-144`).
  - `KNOWN_EXCEPTIONS` is empty (:129).
- Modules the sidecar imports must stay config-free: `corpus_ingest.py`, `document_headers.py`, `schemas/corpus.py` (`test_sidecar_startup.py:58-160`).
- Isolation is a SQL predicate, never a prompt (`docs/06:130-132`). The grounding prompts can be overridden.
- New prompt purposes must be classified in `RUN_PURPOSES` or `NON_RUN_PURPOSES` (`prompt_composition.py:116-141`).
- Do not deepen the session path. A general chat assistant is declined (`docs/10:85`).

### 4.8 Packaging excludes
- **hiddenimports.** Every lazily imported parser must be listed in `research-sidecar.spec` hiddenimports (:81-84).
  - Nothing tests that list.
  - No packaged check uploads a corpus file (`desktop.yml:116-183`; `check_packaged_sidecar.py:216-260`).
  - `ImportError` therefore surfaces as a desktop-only 500 while CI stays green.
- **Excludes.** The excludes are weasyprint, celery, redis, asyncpg, psycopg, alembic, pytest and tkinter (spec:99-108). The import-tree test walks only `LAZY_REQUEST_IMPORTS` (`test_sidecar_startup.py:235-271`), so add the corpus ingest path to that walk.
- **Wheels.** Python 3.14 is the only supported version (A10.06). Compiled parsers need cp314 wheels for macOS arm64, win_amd64 and manylinux x86_64/aarch64. `unstructured` declares `<3.14`.
- **Licence.** The repo is MIT. pymupdf is AGPL; odfpy offers GPL/LGPL options. Constitution §16 and §34 require a licence check.
- **Bundle size.**
  - There is no size ceiling, only floors (`desktop.yml:357-386`).
  - The size claims are hand-written. pandas or pyarrow would make "heaviest dependency is numpy" false.
  - Do not measure from `backend/dist` (1.7 GB, polluted with torch and jaxlib) or `backend/.venv` (Python 3.11, stale).
- **Release wiring.** A new `desktop.yml` step must be added to `DESKTOP_TAG_STEPS` (`scripts/release_checks/workflows.py:170-195`).
- **Tauri dialog plugin.** Adding one means a Cargo dependency, a capability permission and a frontend `@tauri-apps` package. All three frontend builds must then be run.

### 4.9 Schema, evals, release and frontend mechanics
- **Corpus SQLite.** Changes go only through `_migrate`. `schema_version` is never updated on existing rows. There is no downgrade path and no populated upgrade fixture.
- **Relational changes.**
  - They need Alembic, the ORM model and the desktop sync. New columns must be nullable or have a server default (`sidecar.py:476-487`).
  - References that cross databases have no FK, so cleanup must be explicit (the AGENTS.md polymorphic-reference rule).
  - Add new tables to `V2_TABLES` (`tests/task/test_schema_parity.py:42-56`).
- **Evals.**
  - Results are write-once (CI job `eval-artifacts`, `ci.yml:413-438`).
  - A retrieval change needs a measured result before and after (`docs/08:182-185`).
  - A2.03's `QUALITY_PATHS` includes `retrievers.py` and `tools.py`, but not `corpus.py`, `documents.py` or `chunking.py` (`scripts/release_checks/constants.py:118-129`).
- **Versioning.**
  - A bundle v3 is refused by 3.0.x verifiers (`verify_bundle.py:67`, supported versions {1,2}). Under M0.03 that means a major release (`RELEASE.md:256-258`).
  - The verifier must ship before any producer emits the new version.
- **Docs.**
  - Docs change in the same PR: `docs/34:469-487`, `docs/05:233-247`, `docs/13:69-75/142/174-205`, `docs/06:261-271`, `docs/25:22-25`, `docs/28:127-146`, `docs/36:159-171`, plus the roadmap, changelog, `releases.ts` and `features.ts`.
  - Doc numbers are stable, and the next free published number is 39. Planning documents belong in `internal/`.
- **Frontend.**
  - CI greps (`ci.yml:127-147`) cannot tell a use from a mention; verify with GNU `/usr/bin/grep`.
  - Colors come from tokens only. Do not set state inside effects.
  - The active project comes from the `ActiveProject` context, not a route param, and the root Providers must not fetch.
  - The desktop static export needs routes that use query params.
- **Logging.** Bind a run as `run_id`, never `session_id` (`backend/AGENTS.md`).

## 6. Open questions only the owner can answer

1. **Name and number.**
   - The request stops at "Let's call it". What is the release or feature name?
   - Is it v3.1.0 (additive)? Or v4.0.0, if the selection goes into a bundle v3, or the corpus schema change is treated as not downgradable (`RELEASE.md:256-258`)?
   - Does a 3.0.3 patch ship first? Seven PRs (#200–#206) have merged since the tag, and `releases.ts:76-78` promises three items "Fixed for the next release".
2. **Surface.**
   - Is "ask these files" a research run (plan gate, report, approval, bundle) restricted to a selection, or a new lightweight Q&A surface?
   - If the latter, it collides with the declined "general chat assistant" (`docs/10:85`) and needs an RFC argument.
   - Either way, the session path must not be deepened, and project chat is server-only.
3. **How strict "ONLY from selected files" is.**
   - Does it cover retrieval only, or must uncited prose and Limitations also be barred from model prior knowledge?
   - Should a question the selection cannot answer fail the run, or produce an explicit "not in your files" answer?
4. **Model locality.**
   - Must selection runs use local models, so that "nothing leaves the machine" becomes true?
   - Or should the release narrow the claim per privacy tier, and fix the five or more surfaces that overclaim today (C7)?
5. **Session builders (C1).** Does the selection reach `pipeline_runner` and `_drive_session` (for example as an explicit "whole corpus"), or only the run builders?
6. **Selection identity and lifetime.**
   - Does a selection name version ids or `doc_key`s?
   - Is it resolved once at run start (frozen, like `prompt_overrides`) or re-resolved on resume?
   - What happens when a selected document is superseded or deleted mid-run?
   - What do "nothing selected" and "a selection that resolves to zero current documents" mean?
7. **Selection persistence.** Should selections be ephemeral per request, saved named collections, or both? And is the resolved selection recorded in the bundle: in `sources` dicts (minor release) or as a top-level field (major)?

   - Can the same file sit in two folders?
   - What do rename, move and delete do?
   - Are folders global on desktop or per project?
9. **Desktop.**
   - Does this release add real per-project corpus isolation on desktop?

10. **Formats in scope for v1.**

    - Should parsers be pinned exactly so both hosts extract identical offsets?
11. **Spreadsheet semantics.**
    - Cite cached values or formulas?
    - Index hidden sheets?
    - How are merged cells and very wide sheets handled?
    - Is a character-offset citation enough, or must citations name sheet, row and cell (a new locator key plus a UI change)?
12. **Derived text.** Should OCR'd or linearized content get its own attestation grade (CHECK widening plus a desktop table rebuild), or a label only?
13. **Small selections.** Should one- or two-file selections relax the critic's 2-source rule and the one-hit-per-document retrieval cap? Changing the cap is a measured retrieval change.
14. **Limits.**
    - Maximum selection size and files per folder upload.

    - A desktop bundle-size ceiling, given that no ceiling exists today.
15. **Process.**
    - Should the RFC use a version-scoped label (`internal/rfcs/V3.1-corpus-*.md` with PR-n/AC-x/D-n)? `M20`–`M22` are already release-check IDs.
    - Should `corpus.py`, `documents.py` and `chunking.py` join `QUALITY_PATHS`?
    - Does the new user-guide page take number 39?
